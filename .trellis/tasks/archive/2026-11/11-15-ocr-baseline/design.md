# Design

## Boundary and reuse

Keep all changes in benchmark tools, new synthetic tests, documentation and Trellis artifacts. Import reviewed helpers from `batch_assess` for inventory/ID selection, location/alias checks, atomic JSON, fsynced append, JSON duplicate-key rejection, incomplete-tail recognition, quiet read-only/network guards, memory Apple bridge, semantic projection and field vocabularies. Use a PDF-only filter before ID selection. If a generic persistence helper must be factored out, preserve batch signatures, schemas, CLI output and all old tests.

Reuse `batch_assess._read_pages` for independent content classification, existing extractor/conversion calls and finalization. Give it a tool-owned neutral virtual PDF name, not a source filename, so fallback adapters cannot accidentally infer type from names. Only one in-memory page is passed at a time. The benchmark measures page-local extraction, not complete multipage/application accuracy. Never call `_assess`, `assess_upload` or verdict benchmark functions.

Trellis helper skills are not installed in the project or the searched Codex skill/plugin directories. Planning follows `.trellis/workflow.md` directly. Context manifests carry the relevant specs and research for the later implementation/review phase. Plan approval received on 2026-11-15; implementation may start.

## Input eligibility and text quality

- Reuse `TEXT_LAYER_MIN_CHARS` (currently 50) and the preprocessing masked, stripped text-length rule without rendering rejected pages. Label zero text and short text separately within no-trusted-text-layer totals.
- On a candidate page, inspect unmasked text in memory. Count Unicode replacement characters, Unicode category `Co` (all private-use planes), invalid controls excluding whitespace, and unusable word geometry. Proposed broken-layer rule: replacement ratio >= 1%, private-use ratio >= 5%, combined replacement/private-use/invalid-control ratio >= 5%, or no usable reference words. Denominator is non-whitespace code points. Thresholds live beside transform settings, appear in reports, and are resume-bound. They are benchmark heuristics, not changes to production eligibility.
- Classify eligible reference pages with existing `pdftext.classify_pages_with_evidence`; unknown pages are excluded from metrics. A page with no recognized type is not assigned the neighboring page's type.
- Count encrypted/corrupt/zero-page files at document level; count no-layer/broken/unknown pages at page level. Persist fixed codes only. A known zero-page document differs from an inaccessible page count.

## Deterministic variants and geometry

One `SETTINGS` structure owns version, seed (proposed 20261115), DPI/JPEG/blur/rotation/perspective parameters, quality thresholds, bins and overlap thresholds. Phone perspective corner offsets are bounded to 1% of each dimension, sampled from a local PRNG. Derive a stable per-document/page seed from the fixed seed, root-relative ID and page index; record only its integer. Derivation does not depend on inventory order, selection, engine or previous calls.

Use PyMuPDF rendering and installed image libraries entirely in memory. JPEG variants are encoded to BytesIO and decoded, then supplied through the existing PNG-byte engine interface; no image sidecars. Use the same variant bytes for both engines. Retain the forward homography and inverse only in memory. Transform OCR box corners back to page coordinates for CER ordering, matching, font-height and table attribution. Keep OCR boxes in actual image coordinates for production extraction. Do not geometrically correct the input image before recognition.

The field reference is extracted once from original text-layer geometry at clean-equivalent resolution; it is fixed across variants. Thus phone field losses include OCR-induced geometry/structure sensitivity, not just glyph differences. All CER variants share the same original text truth. Reference/OCR extraction both retain normal production masking and independent classification; no expected-type oracle.

## Masking observation

Own and Apple adapters mask some identifiers before returning `OcrWord` data. Comparing unmasked truth against masked output would falsely call redaction an OCR error. Add scoped, tool-only observers around the existing masking call sites: deep-copy the incoming word objects before mutation, then call the original masking function unchanged. Raw snapshots feed only in-memory OCR metrics; the normal masked result feeds extraction. Never disable masking, replace recognition output, change engine source or persist raw snapshots. Restore all observers on errors/interrupts. Test complete and split synthetic identifier cases and repeated masking calls.

## Metrics and denominators

- Reading order: reuse `layout.normalize` and `layout.group_lines(tol=0.6)` on original-page coordinates, independently for truth and OCR. Its center-distance rule uses the current word height with a minimum height of 0.3% of page height. Sort lines by vertical center and words within each line by left edge, with deterministic geometry tie breaks. Report this method/version; never optimize order using text matches.
- CER: Levenshtein edits / normalized reference characters; do not clamp values above 1. Persist edits and character counts. NFKC then remove all Unicode whitespace. Digits use ASCII digits after NFKC; Hangul includes syllables and Jamo Unicode ranges after NFKC. Empty reference denominators yield null CER with insertion counts preserved, not artificial zero.
- Words: split reconstructed geometric lines on Unicode whitespace after NFKC. Count exact token multiset intersections. Precision, recall and F1 retain numerator/denominator counts; empty denominators are null. Engine tokenization/spacing differences remain visible.
- Field vocabularies: reuse `batch_assess.FIELDS`, `_field_values`, `_semantic_field` and typed equality. Both sides first receive identical production word masking and then identical `documentai_staged.canonicalize` normalization of the existing semantic projection; match means typed equality of these normalized values. Missing references are counted by every reviewed field; present-reference plus absent observed value is X. Type mismatch cannot disappear from denominators. Label these as reference-relative agreement, never extractor truth accuracy; point to existing synthetic v2 reference reports separately.
- For the mismatch-cause diagnostic, normalize scalar leaf values with NFKC/whitespace removal, preserving semantic list order. Require every nonempty reference leaf to occur literally in the normalized OCR stream; do not include dictionary keys or JSON delimiters. All-present => structure/extractor; any-absent => OCR. Reference values already absent from reference text, such as derived fields, get a separate non-literal/not-attributable count, not a forced cause. Persist only O/X/counts, not leaves or presence substrings. This is an operational heuristic, not proof of causality.
- Summaries include page CER mean/median/p90 plus pooled edits/reference characters; digit/Hangul metrics; word counts and F1; and per-field matched/eligible/missing-reference counts. Separate successful measurements, classification losses, engine unavailability and processing errors.

## Attribution

- Build reference lines in page coordinates. A detection overlap is positive intersection with intersection area / smaller box area >= 0.1. A reference line has detection coverage if any OCR box meets that threshold. For line-text attribution, assign each OCR box once to the reference line with maximum qualifying intersection, breaking ties geometrically. Report coverage and ambiguity counts, so large multi-line boxes do not silently duplicate text.
- Detection-miss rate counts reference lines without a qualifying box. Recognition CER pools edits/characters on covered reference lines, reporting covered-but-empty-assigned lines separately. It is box-coverage analysis, not model-internal detector recall: empty recognized lines can be filtered by the existing engine.
- Height bins use median reference word-box height after scaling to the variant's actual image (not font metadata): <12, 12–<20, 20–<32, >=32 px. Persist bin counts, edits, characters, missed/covered lines; label these glyph-box-height proxies.
- Table support is partial. Reuse the existing resident extractor `_table_bounds` where it identifies a history-table band, using reference geometry only; classify by reference-line center within the band. Report it explicitly as a full-width table-band estimate, not exact cell segmentation. NHIS payment is also mandatory: apply existing legacy `_month_header`, `_header_block`, month regexes and monthly-row extraction, and government-form header/month/column helpers to reference-only geometry. Define a bounded rectangular region from confirmed headers and month rows (including an available total row); report inside/outside CER, inside digit CER and detection misses. If headers/month rows cannot establish a region, mark it unmeasured. Other forms lack a shared complete region interface; report unsupported/not-detected coverage and null inside/outside metrics rather than inventing new table detection. No remote table engine.
- Confidence bins: [0,.5), [.5,.8), [.8,.9), [.9,1]; non-finite/out-of-range scores count as unavailable. Use each covered line's character-weighted mean OCR confidence and its reference-relative CER plus incorrect-line count. Report counts and denominators. Missed lines have no confidence and stay in the detection population; confidence is not a calibrated probability and differs by engine.

## Timing

Run sequentially. Time actual engine calls separately. Observe own `_detect` and recognition-session calls through scoped delegating wrappers without altering their arguments, results, sessions or threading. Report model/session initialization and residual preprocessing/postprocessing separately so detector and recognizer times are not falsely claimed to sum to OCR wall time. Apple only exposes whole-call timing; split values remain null.

Whole processing = OCR wall time + same-page classification/extraction/finalization time; exclude rendering, transforms, metric work and reference extraction. Report reference extraction timing separately. Record actual ONNX session intra/inter thread counts, worker count=1, numeric cold-start flags. For native opaque thread settings use null/unknown, never serialize arbitrary environment strings. Provide mean/median/p90, with cold first calls identifiable.

## Persistence, resume and reporting

- `run.json`: closed schema with tool/policy version, opaque resolved-root digest (not absolute path), engine/variant list, numeric settings, seed and reviewed numeric execution settings. Root digest binds location only; never hash document text or field values.
- `results.jsonl`: one atomically committed document completion record with bounded page exclusions and page × engine × variant numeric records. This keeps `--ids` and continuation document-based. Completed exclusions/errors are terminal, as in batch. An interrupted document reruns; completed documents never do. Page numbers are 1-based original PDF indices.
- Validate all persisted objects against closed positive schemas before append and on resume/summary. Engine/type/field/error keys must be fixed vocabularies. Store only reviewed identifier exceptions and numeric/null/O/X data; no arbitrary metadata/exception class strings.
- Reuse path privacy, symlink/hardlink/overlap protection, advisory locking, fsync and strict tail recovery. Validate run identity before repairing data. Check source/ID-list aliases against all output files, including new summaries, before mutations. Never truncate interior corruption or retry completed errors implicitly.
- `summary.json` and `summary.txt` are numeric aggregate projections refreshed atomically after a run. Explicit `--summarize` recomputes and prints JSON plus text from persisted records without importing OCR/model backends, traversing root or mutating files, preserving batch's read-only summary semantics. Explain this distinction in the CLI docs.
- Progress contains counts and elapsed seconds only. Run/summary top-level errors use fixed exit codes without argument echo, messages or tracebacks. Numeric-table labels and operational enums are the allowed schema vocabulary; numeric-only means no source values, not unlabeled tables.

## Validation isolation and rollout

Use newly authored synthetic PDF/image bytes only. Backend test-package initialization automatically inspects its fixture directory. Before running regressions, prepare an ignored isolated source copy using tracked files only, with newly generated synthetic samples; link only dependency environments, installed model assets and fonts. Do not copy or inspect existing ignored input, upload or database trees. Run requested commands there and explain the isolation in the report. If a regression fails, report its reason before any remediation; preserve all existing test files.

Actual-engine smoke uses one authored document and both requested installed engines across three variants. Report setup/availability, actual per-page measurements and an estimate `pages × sum(engine/variant processing seconds) + rendering/transform overhead`; only one document is a weak throughput estimate. The 30-document operator pilot provides a better median/p90 estimate. No real-input inventory is needed to offer page-count examples.

Rollback is removal of the new tool/tests/docs; no service/model migrations. No source-path-bearing real-run commands enter tracked artifacts. Commit remains explicitly gated after tests, full review and staged sensitive-string checks. Proposed updated message: `tools: OCR baseline (CER, field accuracy, speed) on text-layer pages`.
