# Design
Keep one directed household edge in the submitting Review payload; reverse officer projection reads submitted source reviews and does not mutate destination records. Reuse existing reason UI. Existing scope uses program and created_at.year; no round model exists, criteria_version is a rules version, not an intake round. Do not invent a round rule.
Keep guard-v3 UPDATE and INSERT definitions unchanged. Add BEFORE DELETE ABORT and BEFORE UPDATE immutable (id, application_id) guard. Thus application_id is a lifetime Review identity while the schema remains intact; CAS revision cannot be reset by supported DML. No new generation column/API break. Backup restore, DDL privilege and DB copies remain explicit limits requiring rollout/session invalidation. Migration installs exact guards atomically with BEGIN IMMEDIATE; wrong definitions fail closed. Ordinary deletion tools reject reviewed applications; seed cleanup retains reviewed synthetic records.

Independent review addition: protect reviewed Application parent deletion/id reuse and unique application_no REPLACE victim conflicts with three additive parent guards. No new table/column is needed. Do not erase reviewed synthetic seed rows; create new isolated DBs.
