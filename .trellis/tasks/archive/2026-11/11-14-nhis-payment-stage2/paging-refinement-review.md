# 쪽수 표시 근거와 표 완전성 보완 검토

상태: 사용자 검토 대기. 기존 시험 입력·헬퍼·단언은 변경하지 않았다. 아래 보완은 무시 대상의 별도 소스 복사본에서 임시 래퍼로 비교한 실험이며, 운영 코드에 반영하지 않았다. 공용 원본 픽스처, 410쌍 측정 입력·정답·지표도 그대로다. 커밋·스테이징 없음.

## 1. 실제 양식에 쪽수가 항상 있는가

**항상 인쇄된다고 단정할 근거를 확보하지 못했다.** 표시가 있는 사례의 존재와 모든 발급 양식의 의무 항목이라는 명세는 서로 다르다.

- [정부24 건강보험료 납부확인서 민원 안내](https://www.gov.kr/mw/AA020InfoCappView.do?CappBizCD=SG4CADM2017&HighCtgCD=A06001): 인터넷·방문 발급과 서비스 범위를 설명한다. 안내의 ‘신청서 없음’은 신청서에 관한 설명이며, 출력 확인서의 쪽수 표기 명세가 아니다. 공개 안내에서 전 발급본 공통의 쪽수 필수 규정은 확인되지 않았다.
- [국민건강보험공단 증명서 발급 안내](https://www.nhis.or.kr/static/html/wbmh/b/wbmhb0412.html): 프린트 미리보기·인쇄와 팩스 전송을 안내한다. 모든 양식·발급 경로·버전에 쪽수가 필수라는 규격은 제시하지 않는다. 공개 안내로 확인하지 못한 부분을 ‘쪽수 없는 양식이 공식적으로 존재한다’는 결론으로 바꾸지는 않는다.
- 저장소 `engine_v2/tests/p2_payment_samples.py::payment`에는 쪽수 토큰이 없다. 기존 `p2_shape3_samples.py`의 납부확인서 단어 목록과 `test_nhis_extractors.py`의 구형·월 단독 표 헬퍼도 완전한 쪽수 표시를 보장하지 않는다. 이들은 합성·관찰 배치 픽스처로, 실제 전 양식의 명세를 대체하지 않는다.
- `engine_v2/tools/documentai_synth.py::sources`는 납부확인서 합성 서류를 만들 때 별도로 쪽수 표시를 추가한다. v2는 이 원본 배치를 유지한다. 따라서 410쌍에서 쪽수를 읽는다는 사실만으로 실양식의 필수 여부를 일반화할 수 없다.

지정된 5개 덤프만 읽었다. 원본 PDF·이미지나 저장소 밖 비공개 파일은 열지 않았다. 가려진 숫자를 쪽수로 해석하거나 날짜·금액 추출기에 넣지 않았다. 아래 O는 **전체 쪽수 표시 형태가 한 단어로 존재하고 관찰 신뢰도 기준을 충족**한다는 뜻이다. 숫자가 가려져 있으므로 실제 현재 쪽·전체 쪽의 값이나 정확도를 검증했다는 뜻은 아니다.

| 덤프 | own 단어 목록 | applevision 단어 목록 | 글자층 단어 목록 |
| --- | --- | --- | --- |
| p001 | X | X | X — 글자층 없음 |
| p002 | O | O | X — 글자층 없음 |
| p005 | O | O | X — 글자층 없음 |
| p006 | O | O | O |
| p010 | O | O | O |

p001의 X는 두 OCR 단어 목록에서 완전한 쪽수 표시 형태를 확인하지 못했다는 뜻이다. 원본에 표시가 없었는지, 잘렸는지, OCR이 놓쳤는지는 이 덤프만으로 구별할 수 없다.

**추가 발견: 엔진 인식과 새 쪽수 검증기의 채택을 구별해야 한다.** 위 4건은 오른쪽 위쪽의 별도 표시를 단어 목록에 보존하지만, 현재 추가한 `payment_paging._page_marker`의 탐색 범위보다 아래에 있다. 따라서 새 검증기는 이 덤프 5건 모두에서 완전한 표시 근거를 채택하지 못한다. 좁은 상단 범위 가정의 누락이다. 덤프 값을 그대로 재사용하지 않고, 표·제목과 분리된 상대 배치를 갖는 독립 합성 재현 시험을 먼저 만든 뒤 탐색 조건을 보완해야 한다. 숫자나 원 좌표를 이 문서에 옮기지 않았다. 증거: `masked-folio-observations.json`.

## 2. 표 완전성 보완의 격리 실험

제안 순서:

1. 확실한 인쇄 전체 쪽수보다 받은 해당 서류의 쪽이 적으면 `PAGES_INCOMPLETE FAIL`. 표 추출 성공이나 합계 일치로 해제하지 않는다. 다른 종류의 첨부 쪽으로 누락을 채우지 않는다.
2. 쪽수 근거가 불확실할 때만, **같은 원본 단어에서 추출한** 표 완전성 증거를 확인한다. 요구된 대상 월이 모두 있고 인쇄된 합계가 실제로 존재하며 월별 합계와 일치해야 한다. 읽힌 조회기간이 있으면 그 기간의 월도 모두 있어야 한다.
3. 표 완전성이 증명되면 쪽수 불확실 사유만 제외한다. 기존 조회기간 충돌·미판독, 월별 금액 불확실, 신원·용도·화질·소득 검증은 그대로 수행한다. 표 완전성이 증명되지 않으면 `NHIS_PAYMENT_PAGING_UNCERTAIN NEEDS_REVIEW`. 쪽수 불확실만으로 화질 FAIL이나 재업로드 안내를 만들지 않는다.

실험의 표 증거:

- 정부형 8열: 월별 행·연속성·숫자·머리글·열·합계 행·8개 열 합계·납부 총액·숫자 교정 검증을 모두 명시적으로 확인하고, 인쇄 합계 자료의 존재와 8개 항목을 요구했다. 분리된 연말정산은 기존 열 합계 검증에만 반영하고 월별 금액과 평균에는 넣지 않았다.
- 구형 표: 원본 단어를 처리하는 기존 `_extract_monthly`에서 고지 합계가 실제로 관찰되었는지 별도로 확인했다. 읽힌 납부 합계도 있으면 그 일치를 요구했다. 대상 월·연속성·숫자·고지 합계 일치를 확인한다. 건강/장기요양의 분리 여부 등 소득 판단 조건은 기존 판정을 유지한다. 쪽수 사유를 해제하는 것만으로 새로운 금액이나 소득 근거를 만들지 않는다.
- 기존 `monthly_total_matches`와 `paid_total_matches`는 인쇄 합계가 없어도 참일 수 있다. 두 불리언만으로 표 완전성을 증명하면 안 된다. 합계 항목이 실제로 없는 구형 표를 추가 음성 시험으로 확인했다.
- 이 실험은 안전한 운영용 영속 필드 스키마 구현을 대체하지 않는다. 실제 반영 시에는 같은 문서·같은 판독 결과에서 만든 증거만 전달하고, 과거 행의 누락/변조된 증거나 잘못된 쪽수 메타데이터를 무조건 해제하는 우회가 없도록 별도 검증해야 한다.

### 기존 26개 영향 사례

| 항목 | 보완 전의 쪽수 검증 | 제안 보완 격리 실험 |
| --- | --- | --- |
| 기존 PASS 단언 24개 | 입력 그대로면 NEEDS_REVIEW | 기존 PASS 단언 그대로 통과 24개 |
| 기존 소득 단언 2개 | MET/OVER_LIMIT → UNDETERMINED | MET/OVER_LIMIT 및 blocker 단언 그대로 통과 2개 |
| 영향이 남은 사례 | 26개 | **0개** |

동일한 26개 매개변수 사례를 기존 입력·기존 단언으로 실행: **26 passed**. 기존 영향 목록의 시험별 결과는 `paging-table-experiment.json`에 기록했다. 현재 결과로는 이 26개 시험에 쪽수 표시를 추가하는 입력 보완이 필요하지 않다.

| 사례/경로 | 원래 기준 | 세 추출 수정 + 쪽수 검증 | 표 완전성 보완 격리 실험 |
| --- | --- | --- | --- |
| `s1_nhis_payment_pages_incomplete` own | NEEDS_REVIEW — 표 추출 사유 | PAGES_INCOMPLETE FAIL | **PAGES_INCOMPLETE FAIL** |
| 같은 사례 글자층 참조 | PASS — 기존 잘못된 통과 | PAGES_INCOMPLETE FAIL | **PAGES_INCOMPLETE FAIL** |

원래 측정 입력의 지문과 동일한 합성 서류를 재생성하고 실제 own OCR 및 글자층 참조 경로를 실행했다. 두 경로 모두 최종 FAIL의 사유는 `PAGES_INCOMPLETE`다. `paging-target-table-experiment.json` 참조.

추가 격리 합성 시험 **24 passed**: 완전한 표 + 없는/부분/저신뢰 쪽수는 쪽수만으로 하향하지 않음; 확실한 누락은 표 성공/실패와 관계없이 FAIL; 표시 없음 + 머리글 손상/합계 불일치/월 누락/합계 없음은 REVIEW; 요구 월 부재는 면제하지 않음; 연말정산·경계 잘림·이웃 머리글 분리 후에도 원래 월별 금액과 평균 유지. 기존 시험을 보완 규칙에 맞춰 고쳐서 얻은 결과가 아니다.

## 범위와 다음 승인 지점

이번 보고는 요청된 근거 조사와 규칙 보완 검토 결과다. 운영용 표 완전성 증거 전달·검증이나 탐색 범위 보완은 이 결과 검토 후 진행한다. 현재 시험 입력 보완은 제안하지 않는다. 보완을 실제 구현한 뒤 새 판정 규칙용 시험을 추가하고, 기존 기대값이 바뀌는 사례는 다시 별도 승인받는다. 최종 소스에서 원래 기준과 동일한 410쌍 전체를 다시 비교해 잘못된 통과·잘못된 불합 비증가 및 NEEDS_REVIEW 변화를 확인해야 한다. 이번 격리 결과를 전체 측정 통과나 커밋 승인 요청으로 제시하지 않는다.


## 별도 기록: 표 완전성 보완 전 소스의 전체 측정

사용자 검토 중 병행 실행하던 기존 쪽수 검증 소스의 v2 측정은 410쌍 / 820경로 / 실행 실패 0으로 완료했다. 원래 기준과 모든 입력 지문이 같다. 새 잘못된 통과·새 잘못된 불합은 0이다. 전체 잘못된 통과는 own 0→0, 참조 20→15; 납부확인서 참조의 기존 잘못된 통과가 10/50→5/50으로 줄었다. 확실한 잘못된 불합은 두 경로 모두 0→0이다. 전체 NEEDS_REVIEW는 own 255→232(새 REVIEW 전환 5건, 해소 28건), 참조 250→250. 새 REVIEW 5건은 납부확인서의 low_resolution 음성 사례이며 PASS로 바뀌지 않았다. 다른 서류의 판정 변화는 없다.

이 측정은 이번 표 완전성 보완과 탐색 범위 보완을 **포함하지 않는다**. 따라서 최종 후보의 410쌍 검증 완료나 커밋 승인 근거로 사용하지 않는다. 상세: `paging-strict-measurement-comparison.json`, `paging-strict-payment-field-metrics.json`. 최종 보완 구현 뒤 전체 측정을 다시 해야 한다.
