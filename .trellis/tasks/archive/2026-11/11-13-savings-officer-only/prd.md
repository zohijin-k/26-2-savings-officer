# 두배적금 담당자 전용 저장소 정리

## Goal
26-2-capstone에서 분리한 이 저장소를 두배적금 담당자 화면 전용으로 정리한다. 2026-11-13 사용자가 최종 계획을 승인하여 구현한다. 커밋은 별도 승인 전 실행하지 않는다.

## Requirements
- R1: 안내·사업/신청자 선택 없이 두배적금 담당자 화면으로 바로 진입한다.
- R2: 신청자 프런트엔드 라우트·컴포넌트·내비게이션과 취업지원 담당자 화면·필터·메뉴를 제거한다.
- R3: 첫 화면에는 문서 상태 PASS인 '적합 서류', 그 외 모든 상태인 '확인 필요 서류' 두 목록만 표시한다. 저장된 판정은 변경하지 않는다.
- R4: 확인 필요 항목 선택 시 왼쪽 원본 서류, 오른쪽 기존 사유 코드·안내를 표시한다.
- R5: 신청 API·판정 저장·DB 모델·engine_v2를 보존한다. 기존 시드/합성 시나리오를 조사하여 시연 데이터 주입 방안을 계획하며 승인된 seed_officer_demo CLI를 추가한다.
- R6: 루트 README를 담당자 전용 설명, 안내/형제 저장소 링크, 지정 실행 명령, 합성 시연 데이터 절차로 재작성한다. docs/DEVELOPMENT.md와 demo/README.md는 달라진 사실만 최소 수정한다.
- R7: 실제 서류와 금지된 데이터 디렉터리를 시험 입력으로 열거나 사용하지 않는다. 합성 데이터만 사용한다.
- R8: 기존 시험 기대값 변경/삭제는 파일·시험 이름·이유를 먼저 보고해 승인받는다. 화면 제거에 따른 삭제는 별도 묶음으로 보고한다.
- R9: 작업 전 네 갈래 기준선을 확인하고, 커밋 전 git diff --stat main과 네 갈래 결과 비교를 보여 승인받는다.

## Acceptance Criteria
- AC1 (R1–R2): 루트/새로고침에서 두배적금 담당자 화면이 나오고 신청자·취업지원 진입 요소가 없다.
- AC2 (R3): 두 목록의 분류는 문서 PASS 여부만 사용하고 원래 상태·판정·사유를 보존한다.
- AC3 (R4): 확인 필요 항목이 선택한 원본과 기존 사유를 2단으로 표시한다.
- AC4 (R5, R7): 백엔드/엔진 계약과 시험을 보존하고 합성 데이터로 두 목록·상세를 시연할 수 있다.
- AC5 (R6): README 저장소 링크·실행·데이터 절차가 실제 동작과 맞는다.
- AC6 (R8–R9): 시험 변경 승인 내역·작업 전후 검증 결과를 기록하며 커밋 전 승인을 기다린다.

## Out of Scope
판정 로직, 사유 세부 설계, 신청자 저장소 연결, OCR 정확도·속도. 백엔드 신청/취업지원 계약 삭제나 데이터 마이그레이션도 수행하지 않는다.

## Approved implementation constraints (2026-11-13)
- phone.test.ts 삭제와 seed_officer_demo 추가 승인. 다른 기존 시험 삭제·기대값 변경 필요 시 즉시 중지·보고한다. P4 allowlist 정리도 기존 시험을 건드리지 않고 그대로 남긴다.
- 시드는 저장소의 합성 samples만 사용하며 외부/실제 서류나 금지된 데이터 디렉터리를 입력·참조하지 않는다. 로컬 데모 DB에서만 동작한다.
- 정상 한 건의 모든 서류 PASS, 확인 필요 한 건은 최소 하나 non-PASS. 실제 화면의 두 목록 분리까지 시험한다.
- 자체 생성 표시로 중복 생성을 방지하고 --clean은 자체 생성 행·저장 파일만 지운다.
- 신청 API·판정 저장·DB 모델 및 engine_v2 판정 로직 불변. 기존 저장 판정 불변.
- 커밋 전에 diff stat main, 네 갈래 before/after, 삭제 프런트 파일/라우트 목록, 시드 생성·중복 방지·정리 결과를 제시하고 승인을 기다린다.
