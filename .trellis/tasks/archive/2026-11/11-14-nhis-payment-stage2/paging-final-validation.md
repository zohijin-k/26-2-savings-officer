# 최종 검증 — 커밋 전 검토

상태: 최종 410쌍 측정과 비교 완료. 커밋 승인 대기. 코드·시험 소스는 `engine_v2/data/stage2_paging_final_20261115/src`에 고정했으며, 이전 중단 측정은 비교에서 제외한다. 커밋하지 않았다. 실서류 재측정은 실행하지 않았고 사용자가 수행한다.

## 판정과 범위

두 저장소의 명시 슬롯이 파일 1개를 교체 보유한다는 읽기 전용 조사에 따라, 남은 파일을 해당 칸의 제출 전체로 판정한다. 완전한 형태·충분한 신뢰도·일치하는 전체 쪽수 근거가 있고 표시 전체 쪽수가 파일 물리 쪽수보다 클 때 PAGES_INCOMPLETE FAIL이다. 표가 완전해도 이 FAIL은 면제하지 않는다. 상충·불확실한 표시는 REVIEW이며, 1/1도 PASS 근거가 아니다.

쪽수 검토 사유만 제외하려면 확정된 비충돌 조회기간, 요구 월과 인쇄 조회기간의 모든 월, 실제 인쇄 합계 존재와 월별 합 일치, 받은 쪽에서 판독한 발급 정보가 모두 필요하다. 원본 금액·합계·발급일 표현에 결속된 증거를 검증하므로 변경/손상된 필드가 과거 산술 플래그를 재사용할 수 없다. 기존 조회기간 충돌·미판독 처리와 다른 확실한 실패는 그대로다.

인정하는 표시 문법은 양의 정수 현재쪽/전체쪽이며 ASCII·전각 슬래시, 공백과 토큰 분할을 허용한다. 앞자리 0은 허용하지 않고 현재쪽≤전체쪽, 신뢰도≥.85, 유일한 후보와 쪽 간 전체 쪽수 일치를 요구한다. 쪽 위·아래 여백에서만 보고 표 영역을 제외한다. 날짜·기간·금액의 연결된 전체 토큰 묶음을 먼저 제외해 가로 경계를 넘은 날짜 뒷부분을 쪽수로 만들지 않는다. 표 끝을 못 읽으면 하단을 여백으로 추정하지 않는다.

## 승인된 시험 변경

과거 28개 영향 중 승인한 19개만 조정했다. C2 긍정 5개는 원 단언을 보존한 strict xfail이며 reason은 `C2 header-edge recovery held`다. 경계 횡단 1개는 로컬 합성 상자만 현재 경계를 실제로 가로지르게 옮겼다. 완전 표 면제 12개와 main 구형 조회기간 사례 1개의 판정·소득 신뢰·pipeline 단언은 승인대로 함께 바꿨다. 보류한 기존 9개 FAIL 기대값은 변경 없이 통과한다. 공용 헬퍼에 기간/쪽수를 넣거나 기존 26개에 1/1을 추가하지 않았다.

새 표 불완전 변형 10개는 동일한 다섯 표시/신뢰도 조합 × own·글자층으로 PG REVIEW, 비FAIL, 적절한 화질에서 새 화질 실패 없음도 검증한다. 실제 PDF 두 경로와 두 번 업로드 교체 API를 합성으로 검증했다. 최신 날짜 경계·재무 증거 재현 5개는 수정 전 실패, 수정 후 통과했고, 분리된 실제 쪽수 표시를 유지하는 대조도 통과했다.

## 집계와 안내

경로별 O/X·전체 쪽수 구간·파일 단위 불일치·기간 미확정 면제 차단을 값 없이 집계한다. 기간 차단은 필수 조건 미충족 지표이며 다른 원인과 중복될 수 있다. 폴더 중복은 동일한 첫 하위 폴더에서 같은 종류로 성공 판별된 파일이 둘 이상인 폴더 수이며, 신청자 동일성을 검증하지 않는다. 루트 파일과 오류·미요청·미지원·미분류는 따로 센다. 폴더 파일을 합산해 판정을 바꾸지 않는다. 새 배치 시험 38개와 기존 109개, 합계 147개가 통과했다.

두 저장소 안내와 단일 파일 계약은 `paging-single-file-upload-audit.md`에 기록했다. “모든 쪽을 한 PDF 파일로”라는 officer 문구 변경은 제안만 했고 실제 문구와 applicant 저장소는 수정하지 않았다.

## 최종 410쌍 결과

전체 410쌍 / 820경로, 실행 실패 0. 모든 입력 지문과 원본 생성 메타데이터가 원래 기준선과 같다. 단계·서류·조건·그룹별 잘못된 통과/확실한 잘못된 거부 증가와 새 오통과·오거부 사례는 모두 0이다.

| 범위 | 잘못된 통과 원래→최종 | 확실한 잘못된 거부 원래→최종 | NEEDS_REVIEW 원래→최종 |
| --- | --- | --- | --- |
| 전체 own | 0/235 → 0/235 | 0/175 → 0/175 | 255 → 250 |
| 전체 글자층 참조 | 20/235 → 15/235 | 0/175 → 0/175 | 250 → 250 |
| 납부확인서 own | 0/50 → 0/50 | 0/35 → 0/35 | 65 → 60 |
| 납부확인서 글자층 참조 | 10/50 → 5/50 | 0/35 → 0/35 | 40 → 40 |

새 REVIEW 전환은 두 경로 모두 0. own의 기존 REVIEW 5건은 확실한 쪽 누락 FAIL로 바뀌었다. 글자층 참조의 기존 쪽 누락 오통과 5건이 FAIL로 교정됐으며, 다른 기존 오통과까지 해결했다고 주장하지 않는다. `s1_nhis_payment_pages_incomplete`는 두 경로 모두 PAGES_INCOMPLETE FAIL이다.

납부확인서 필드 정확도(raw/normalized)와 CER은 원래 기준과 동일하다. own 492/910, 참조 765/845이며 called/unextracted/missing 분모·분자가 유지된다. C2는 보류 상태다. 전체 비교와 필드별 수치는 [비교 보고서](paging-final-measurement-comparison.md)와 값 없는 JSON에 있다.

고정 소스의 255개 관련 Python 파일 바이트가 최종 작업 소스와 같음을 확인했다. 공용 픽스처·원본 410쌍 생성기·정답·지표는 변경하지 않았다. 중단한 이전 측정은 모두 제외했다.


## Staged 위생 점검

검토 범위의 코드·시험·규약·값 없는 작업 기록만 스테이징했다. 실제 비밀키 패턴·키 접두어 문자열·비공개 원본 경로·가린 덤프 경로가 staged 파일/본문에 없음을 확인한다. 가린 JSON 5건은 모두 ignored/untracked이며 원본 실서류를 읽거나 값을 전사하지 않았다. 신청자 저장소는 읽기 전용으로 조사했고 수정하지 않았다. 상세는 paging-final-staged-hygiene.json 및 최종 git diff --stat main 출력에 기록한다. 커밋은 아직 없다.
